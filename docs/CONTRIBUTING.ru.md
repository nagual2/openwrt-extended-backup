## Безопасность прежде всего

**ВАЖНО: Безопасность — главный приоритет.** Перед участием прочтите [SECURITY.md](./SECURITY.md).

### Критические правила безопасности

1. **Никогда не коммитьте учётные данные или секреты:**
   - API-ключи, GitHub-токены, SSH-приватные ключи
   - Пароли (используйте тестовые значения или переменные окружения)
   - AWS-учётные данные или другие облачные секреты
   - Любую персонально идентифицируемую информацию

2. **Используйте SSH для git-операций:**
   - Настройте git для использования SSH: `git clone git@github.com:...`
   - НЕ используйте HTTPS со встроенными учётными данными

3. **Защищайте чувствительные данные:**
   - Храните учётные данные в файлах `.env` (добавьте в `.gitignore`)
   - Используйте переменные окружения в тестах
   - Смотрите `.env.example` для настройки тестов

4. **Тестовые учётные данные не должны выглядеть реальными:**
   - Используйте мок-значения типа `TestPass${RANDOM}` в тестах
   - Используйте placeholder-значения, явно указывающие на тестирование
   - Генерируйте уникальные значения для каждого прогона тестов

5. **Pre-commit хуки проверят наличие секретов:**
   - Убедитесь, что все хуки проходят перед push
   - Используйте `gitleaks` для сканирования случайно закоммиченных секретов
   - Исправьте любые обнаруженные проблемы перед отправкой PR

## Начало работы

### Настройка

1. Сделайте fork репозитория
2. Клонируйте ваш fork через SSH:
   ```bash
   git clone git@github.com:your-username/openwrt-extended-backup.git
   cd openwrt-extended-backup
   ```

3. Создайте feature-ветку:
   ```bash
   git checkout -b feature/your-feature
   ```

4. Установите зависимости для разработки:
   ```bash
   # Установка pre-commit хуков
   pre-commit install
   ```

### Внесение изменений

1. **Пишите код следуя существующим паттернам** — изучите похожий код для стиля/конвенций
2. **Тестируйте изменения** — запустите тесты, чтобы ничего не сломалось:
   ```bash
   make test
   ```

3. **Проверьте shell-скрипты** — обеспечьте качество кода:
   ```bash
   make shellcheck
   ```

4. **Никогда не коммитьте секреты** — внимательно просмотрите diff:
   ```bash
   git diff
   git diff --staged
   ```

## Тестирование

### Запуск тестов

```bash
# Запустить все тесты
make test

# Запустить конкретный тестовый файл
bats tests/openwrt_full_backup.bats

# Запустить конкретный тест
bats tests/openwrt_full_backup.bats -f "шаблон имени теста"
```

### Написание тестов

- Используйте описательные имена тестов
- Используйте генерируемые/мок учётные данные (никогда не хардкодьте)
- Очищайте артефакты тестов
- Следуйте существующей структуре тестов

Пример:
```bash
@test "описание теста" {
  # Генерация уникальных тестовых учётных данных
  local test_password="TestPass${RANDOM}"
  export TEST_VAR="${test_password}"
  
  # Код теста
  
  # Очистка
  unset TEST_VAR
}
```
