## Обзор

Этот документ суммирует проблемы безопасности, обнаруженные во время аудита безопасности, и шаги по их устранению.

## Исправленные проблемы

### 1. GitHub Token в конфигурации Git ✅

**Проблема**: Встроенный GitHub Personal Access Token (PAT) в `.git/config`
- **Уровень критичности**: КРИТИЧЕСКИЙ
- **Расположение**: `.git/config` строка 7
- **Тип токена**: GitHub App token (начинается с `ghs_`)
- **Риск утечки**: Высокий — токен был встроен в HTTPS URL с учётными данными

**Применённое исправление**:
- ✅ Удалён встроенный токен из конфигурации репозитория
- ✅ Переключение с HTTPS со встроенными учётными данными на SSH-аутентификацию
- ✅ URL обновлён для использования SSH-аутентификации вместо HTTPS с встроенными учётными данными

**Проверка**: SSH-конфигурация теперь настроена для безопасной аутентификации.

---

### 2. Хардкодные тестовые пароли ✅

**Проблема**: Хардкодный пароль "Secret123" в тестовых файлах
- **Уровень критичности**: ВЫСОКИЙ
- **Расположение**: `/tests/openwrt_full_backup.bats`
- **Вхождения**: 4 instance (2 присваивания, 2 проверки)

**Исправленные расположения**:
1. Строка 229: присваивание пароля для теста SMB export
2. Строка 251: проверка пароля SMB export
3. Строка 262: проверка вывода пароля SMB export
4. Строка 321 & 338: присваивание и проверка пароля для теста ошибки перезапуска SMB

**Применённое исправление**:
- ✅ Замена хардкодного `'Secret123'` на динамически генерируемые пароли
- ✅ Использование паттерна `TestPass${RANDOM}` для уникальной генерации паролей на каждый прогон
- ✅ Все проверки обновлены для ссылки на сгенерированную переменную `${test_password}`
- ✅ Пароли теперь ограничены областью выполнения теста (локальные переменные, не экспортируются)

**До**:
```bash
export KSMBD_PASSWORD='Secret123'
# ...
assert_command_log_contains "ksmbd.adduser owrt_backup -p Secret123"
```

**После**:
```bash
local test_password="TestPass${RANDOM}"
export KSMBD_PASSWORD="${test_password}"
# ...
assert_command_log_contains "ksmbd.adduser owrt_backup -p ${test_password}"
```

### 4. Pre-commit хуки безопасности ✅

**Созданный файл**: `.pre-commit-config.yaml`

**Настроенные хуки**:

1. **gitleaks** — Обнаруживает случайно закоммиченные секреты
   - Репозиторий: `https://github.com/gitleaks/gitleaks`
   - Версия: v8.18.0
   - Запускается при коммите для предотвращения утечки секретов

2. **shellcheck** — Валидация shell-скриптов
   - Репозиторий: `https://github.com/shellcheck-py/shellcheck-py`
   - Версия: v0.9.0.5
   - Валидирует практики безопасности shell-скриптов

3. **Кастомный хук no-hardcoded-secrets**
   - Обнаруживает паттерны хардкодных паролей
   - Исключения: переменные test_password, TEST_*, MOCK_*
   - Блокирует коммиты с потенциальными секретами

4. **Хуки фреймворка pre-commit**
   - `detect-private-key` — Обнаруживает приватные SSH-ключи, сертификаты
   - `check-added-large-files` — Предотвращает коммит больших файлов
   - `trailing-whitespace` — Форматирование кода
   - `end-of-file-fixer` — Консистентность окончаний файлов
   - `check-merge-conflict` — Обнаруживает маркеры конфликтов мержа
   - `mixed-line-ending` — Обеспечивает консистентные окончания строк (LF)

## Для будущей разработки

### Инструкции по настройке

При клонировании репозитория:
```bash
# Используйте SSH (рекомендуется)
git clone git@github.com:nagual2/openwrt-extended-backup.git

# Или настройте git для использования SSH, если уже клонировали через HTTPS
git remote set-url origin git@github.com:nagual2/openwrt-extended-backup.git
```

### Локальная разработка

1. Установите pre-commit хуки:
   ```bash
   pre-commit install
   ```

2. Создайте тестовое окружение (опционально):
   ```bash
   cp .env.example .env
   # Отредактируйте .env с вашими тестовыми значениями при необходимости
   ```

3. Запустите тесты:
   ```bash
   make test
   ```

### Контрибуция изменений

- Всегда просматривайте diff перед коммитом: `git diff`
- Pre-commit хуки будут автоматически сканировать секреты
- Используйте генерируемые/мок учётные данные в тестах, не реальные пароли
- Обновляйте CHANGELOG.md и CONTRIBUTING.md при необходимости
